# PNPT - 2 - 2 =  IP Addresses

## Network Fundamentals – IP Addressing

### أساسيات الشبكات – عناوين IP

#### 1. مقدمة إلى عناوين IP (Introduction to IP Addresses)

قبل أن ندخل في تفاصيل الشبكات، نحتاج إلى فهم أحد أهم المفاهيم التي تقوم عليها عملية الاتصال بين الأجهزة، وهو **عنوان IP (IP Address)**.

ببساطة، عنوان IP هو عنوان منطقي يُستخدم لتحديد الأجهزة داخل الشبكات، ويساعد على توجيه البيانات من الجهاز المرسل إلى الجهاز المستقبِل.

تخيّل أنك تريد إرسال رسالة إلى شخص آخر؛ ستحتاج إلى معرفة عنوانه حتى تصل الرسالة إلى وجهتها الصحيحة. الأمر مشابه تماماً في الشبكات، إذ تحتاج الأجهزة إلى عناوين IP حتى تتمكن من تبادل البيانات.

خلال هذا الدرس سنتعرف على:

* مفهوم عناوين IP وأهميتها.
* الفرق بين IPv4 وIPv6.
* طريقة تكوين عنوان IPv4.
* النظام الثنائي (Binary).
* أسباب نفاد عناوين IPv4.
* مفهوم NAT وآلية عمله.
* عناوين IP الخاصة والعامة.
* نطاقات العناوين الخاصة.

***

#### 2. استعراض عنوان IP عملياً (Viewing IP Addresses)

قبل الدخول في الجانب النظري، دعنا نبدأ بتطبيق بسيط يساعدنا على رؤية عناوين IP الموجودة على الجهاز.

في نظام Kali Linux يمكننا استخدام الأمر التالي:

```
ifconfig
```

يعرض هذا الأمر معلومات واجهات الشبكة (Network Interfaces)، ومن ضمنها عناوين IP المرتبطة بها.

أما في نظام Windows فيمكن استخدام:

```
ipconfig
```

ويمكن أيضاً استخدام الأمر التالي في Windows لعرض تفاصيل أكثر:

```
ipconfig /all
```

عند استعراض معلومات الشبكة قد تلاحظ ظهور نوعين من عناوين IP:

**IPv4 Address**

هو عنوان الإصدار الرابع من بروتوكول الإنترنت، ويظهر عادةً بصيغة عشرية مثل:

```
192.168.1.10
```

**IPv6 Address**

هو عنوان الإصدار السادس من بروتوكول الإنترنت، ويظهر بصيغة سداسية عشرية، مثل:

```
2001:db8::1
```

لاحظ الاختلاف في طريقة كتابة العنوانين:

* IPv4 يستخدم النظام العشري (Decimal).
* IPv6 يستخدم النظام الست عشري (Hexadecimal).

سنفهم سبب هذا الاختلاف عندما نتعرف على طريقة تمثيل البيانات داخل أجهزة الكمبيوتر.

***

#### 3. عناوين IP وطبقات الشبكة (IP Addresses and Network Layers)

تعمل عناوين IP ضمن الطبقة الثالثة من نموذج OSI، والمعروفة باسم:

**Layer 3 – Network Layer**

تُعد هذه الطبقة مسؤولة عن العنونة المنطقية وتوجيه حزم البيانات (Packets) بين الشبكات المختلفة.

على سبيل المثال، عندما يرسل جهازك بيانات إلى خادم موجود على شبكة أخرى، يتم استخدام عناوين IP لتحديد المصدر والوجهة، وتساعد أجهزة التوجيه (Routers) على اختيار المسار المناسب لوصول البيانات.

من المهم أن تتذكر العلاقة التالية:

* IP Address: يحدد العنوان المنطقي للجهاز.
* Network Layer: الطبقة المسؤولة عن العنونة والتوجيه.
* Router: جهاز يربط الشبكات ويوجه حزم البيانات بينها.
* Routing: عملية اختيار المسار المناسب لنقل البيانات.

ستتعرف لاحقاً على نموذج OSI بشكل أعمق، وعندها ستصبح العلاقة بين هذه المفاهيم أكثر وضوحاً.

***

#### 4. تركيب عنوان IPv4 (IPv4 Address Structure)

يُعد IPv4 أحد أكثر إصدارات بروتوكول الإنترنت استخداماً.

يتكون عنوان IPv4 من **32 Bit**، ويتم تقسيمه إلى أربعة أجزاء، يفصل بينها رمز النقطة.

مثال:

```
192.168.1.10
```

كل جزء من الأجزاء الأربعة يسمى:

**Octet**

وكل Octet يتكون من 8 Bits.

لذلك يكون تركيب عنوان IPv4 كالتالي:

| الجزء   | عدد Bits |
| ------- | -------- |
| Octet 1 | 8 Bits   |
| Octet 2 | 8 Bits   |
| Octet 3 | 8 Bits   |
| Octet 4 | 8 Bits   |
| المجموع | 32 Bits  |

وبما أن كل 8 Bits تساوي Byte واحداً، فإن:

```
32 Bits = 4 Bytes
```

إذن، عندما ترى عنواناً مثل:

```
192.168.1.10
```

فأنت ترى تمثيلاً عشرياً لقيمة مكونة فعلياً من 32 خانة ثنائية.

وهذا يقودنا إلى مفهوم مهم جداً، وهو النظام الثنائي.

***

#### 5. فهم النظام الثنائي (Understanding Binary)

تعتمد أجهزة الكمبيوتر في معالجة البيانات على نظام يتكون من رقمين فقط:

* 0
* 1

ويُعرف هذا النظام باسم **Binary** أو النظام الثنائي.

كل خانة ثنائية تسمى Bit، ويمكن أن تكون قيمتها إما صفر أو واحد.

في عنوان IPv4، يحتوي كل Octet على ثماني خانات ثنائية، ولكل خانة قيمة محددة.

ترتيب القيم يكون كالتالي:

| الخانة  | القيمة |
| ------- | ------ |
| الأولى  | 128    |
| الثانية | 64     |
| الثالثة | 32     |
| الرابعة | 16     |
| الخامسة | 8      |
| السادسة | 4      |
| السابعة | 2      |
| الثامنة | 1      |

يمكننا تمثيل هذه القيم بهذا الشكل:

```
128  64  32  16  8  4  2  1
```

**كيف نحصل على القيمة العشرية؟**

عندما تكون قيمة الخانة الثنائية 1، نقوم بإضافة القيمة المقابلة لها. أما إذا كانت 0، فلا نضيف شيئاً.

لنأخذ المثال الأول:

```
11111111
```

جميع الخانات تساوي 1، لذلك نجمع القيم:

```
128 + 64 + 32 + 16 + 8 + 4 + 2 + 1
```

الناتج:

```
255
```

إذن أكبر قيمة يمكن تمثيلها داخل Octet واحد هي 255.

**مثال آخر:**

لنفترض أن لدينا القيمة الثنائية التالية:

```
00000111
```

الخانات التي تساوي 1 هي:

```
4 + 2 + 1 = 7
```

إذن القيمة العشرية المقابلة لها هي:

```
7
```

وإذا كان لدينا عنوان IP بالشكل التالي:

```
7.7.7.7
```

فإن كل Octet يحتوي على القيمة العشرية 7.

**لماذا نحتاج إلى فهم Binary؟**

لأن هذا المفهوم يُعد أساسياً لفهم موضوع تقسيم الشبكات (Subnetting)، وحساب Subnet Mask، وتحديد عناوين الشبكات والأجهزة.

لا تحتاج إلى إتقان جميع تفاصيله من أول مرة، لكن يجب أن تفهم العلاقة بين الخانات الثنائية والقيم العشرية.

***

#### 6. مشكلة نفاد عناوين IPv4 (IPv4 Address Exhaustion)

بعد أن عرفنا أن IPv4 يتكون من 32 Bit، يمكننا حساب العدد الإجمالي للعناوين التي يستطيع هذا الإصدار توفيرها.

بما أن كل Bit يمكن أن يحمل قيمتين (0 أو 1)، فإن عدد الاحتمالات يُحسب باستخدام المعادلة:

```
2^32 = 4,294,967,296
```

أي ما يقارب:

**4.3 مليار عنوان IPv4.**

قد يبدو هذا العدد ضخماً، لكنه أصبح غير كافٍ مع الانتشار الهائل للأجهزة المتصلة بالإنترنت.

فكر في عدد الأجهزة التي يستخدمها الشخص الواحد:

* هاتف محمول.
* جهاز كمبيوتر.
* جهاز لوحي.
* تلفاز ذكي.
* أجهزة منزلية متصلة بالإنترنت.
* كاميرات مراقبة.

ومع زيادة عدد المستخدمين والأجهزة، ارتفع الطلب على عناوين IP بشكل كبير.

عندما بدأ استخدام IPv4 على نطاق واسع، لم يكن من المتوقع أن يصل الإنترنت إلى هذا الحجم.

ومع مرور الوقت، تم تخصيص مساحات كبيرة من عناوين IPv4 للمؤسسات ومزودي خدمات الإنترنت (ISPs)، وأصبحت العناوين العامة المتاحة محدودة للغاية.

لذلك ظهرت الحاجة إلى حل يوفر مساحة أكبر بكثير من العناوين.

وهنا ظهر IPv6.

***

#### 7. ظهور IPv6 (Internet Protocol Version 6)

تم تطوير IPv6 لمعالجة مشكلة محدودية مساحة عناوين IPv4.

الاختلاف الأساسي بين الإصدارين هو حجم العنوان:

| الخاصية      | IPv4            | IPv6          |
| ------------ | --------------- | ------------- |
| حجم العنوان  | 32 Bits         | 128 Bits      |
| نظام الكتابة | Decimal         | Hexadecimal   |
| عدد العناوين | حوالي 4.3 مليار | عدد هائل جداً |
| الفاصل       | نقطة `.`        | نقطتان `:`    |

يتكون IPv6 من 128 Bit، وبالتالي فإن عدد العناوين الممكنة يساوي:

```
2^128
```

وهو عدد ضخم للغاية:

```
340,282,366,920,938,463,463,374,607,431,768,211,456
```

هذا العدد يوفر مساحة هائلة من عناوين IP للأجهزة والشبكات.

مثال على عنوان IPv6:

```
2001:db8:abcd:0012:0000:0000:0000:0001
```

يمكن اختصار بعض الأجزاء وفق قواعد IPv6، ليصبح:

```
2001:db8:abcd:12::1
```

ومن المهم معرفة أن IPv6 مستخدم فعلياً اليوم، وليس مجرد تقنية مستقبلية. ومع ذلك، لا تزال شبكات كثيرة تعتمد على IPv4، وتستخدم آليات مختلفة للتوافق بين الإصدارين.

ومن أبرز التقنيات التي ساعدت على الاستمرار في استخدام IPv4:

**NAT – Network Address Translation**

***

#### 8. ما هي تقنية NAT؟ (Network Address Translation)

NAT اختصار لعبارة:

**Network Address Translation**

ومعناها ترجمة عناوين الشبكة.

تُستخدم هذه التقنية لترجمة عناوين IP أثناء مرور حركة البيانات بين الشبكات، ومن أشهر استخداماتها السماح لعدة أجهزة داخل شبكة خاصة بمشاركة عنوان IPv4 عام واحد.

دعنا نأخذ مثالاً عملياً.

لنفترض أن لديك شبكة منزلية تحتوي على 20 جهازاً، مثل:

* الهواتف المحمولة.
* أجهزة الكمبيوتر.
* كاميرات المراقبة.
* أجهزة التلفاز الذكية.
* أجهزة أخرى متصلة بالإنترنت.

كل جهاز يحصل على عنوان IP خاص داخل الشبكة المحلية.

السؤال هنا:

هل نحتاج إلى 20 عنوان IPv4 عاماً حتى تتمكن هذه الأجهزة من الوصول إلى الإنترنت؟

الإجابة: لا.

هنا يأتي دور NAT.

يقوم جهاز التوجيه (Router) بترجمة معلومات عناوين الاتصال الخاصة بالأجهزة إلى عنوان IP عام عند خروج حركة البيانات إلى الإنترنت.

وفي الاستخدام المنزلي الشائع، تُستخدم تقنية تسمى:

**PAT – Port Address Translation**

وهي تسمح لعدة أجهزة بمشاركة عنوان IP عام واحد، مع التمييز بين الاتصالات باستخدام أرقام المنافذ (Ports).

***

#### 9. عناوين IP الخاصة والعامة (Private and Public IP Addresses)

لفهم NAT بشكل أفضل، يجب أن نميز بين نوعين أساسيين من عناوين IPv4.

**أولاً: Private IP Address**

هو عنوان IP خاص يُستخدم داخل الشبكات المحلية والخاصة، مثل شبكات المنازل والشركات.

مثال:

```
192.168.57.139
```

ومن الأمثلة الأخرى:

```
10.0.0.1
172.16.0.1
```

هذه العناوين لا يتم توجيهها عبر الإنترنت العام بصورة مباشرة.

**ثانياً: Public IP Address**

هو عنوان IP عام يمكن توجيهه عبر الإنترنت، ويتم تخصيصه من خلال مزود خدمة الإنترنت (ISP) أو الجهات المسؤولة عن تخصيص العناوين.

مثال توضيحي:

```
203.0.113.10
```

هذا العنوان من نطاق مخصص للأمثلة والتوثيق، وليس عنواناً عاماً للاستخدام الفعلي.

**الفرق الأساسي بينهما:**

| Private IP                          | Public IP                                 |
| ----------------------------------- | ----------------------------------------- |
| يُستخدم داخل الشبكات الخاصة         | يُستخدم للتواصل عبر الإنترنت              |
| لا يُوجّه مباشرة عبر الإنترنت العام | قابل للتوجيه عبر الإنترنت العام           |
| يمكن إعادة استخدامه في شبكات مختلفة | يجب أن يكون فريداً ضمن نطاق التوجيه العام |
| غالباً يُستخدم مع NAT               | يمكن أن يكون عنوان الخروج إلى الإنترنت    |

***

#### 10. نطاقات عناوين IPv4 الخاصة (Private IPv4 Ranges)

هناك ثلاثة نطاقات رئيسية مخصصة لعناوين IPv4 الخاصة وفق معيار RFC 1918.

يجب أن تحفظ هذه النطاقات لأنها من المعلومات الأساسية في الشبكات والأمن السيبراني.

**النطاق الأول: 10.0.0.0/8**

يُعرف تقليدياً بنطاق Class A الخاص.

النطاق الكامل:

```
10.0.0.0 – 10.255.255.255
```

مثال:

```
10.1.1.1
10.10.20.30
10.255.255.254
```

يوفر هذا النطاق مساحة كبيرة من العناوين، ولذلك يُستخدم كثيراً في المؤسسات والشبكات الكبيرة.

**النطاق الثاني: 172.16.0.0/12**

يُعرف تقليدياً بنطاق Class B الخاص.

النطاق الكامل:

```
172.16.0.0 – 172.31.255.255
```

مثال:

```
172.16.0.1
172.20.10.5
172.31.255.254
```

يُستخدم في تصميم الشبكات الخاصة بمختلف أحجامها.

انتبه: ليس كل عنوان يبدأ بـ 172 عنواناً خاصاً؛ النطاق الخاص يبدأ من 172.16 وينتهي عند 172.31.

**النطاق الثالث: 192.168.0.0/16**

يُعرف تقليدياً بنطاق Class C الخاص.

النطاق الكامل:

```
192.168.0.0 – 192.168.255.255
```

مثال:

```
192.168.1.1
192.168.57.139
192.168.100.20
```

يُستخدم هذا النطاق بكثرة في الشبكات المنزلية والشركات الصغيرة.

**ملخص النطاقات الخاصة:**

| النطاق                        | CIDR | الاستخدام الشائع    |
| ----------------------------- | ---- | ------------------- |
| 10.0.0.0 – 10.255.255.255     | /8   | شبكات كبيرة         |
| 172.16.0.0 – 172.31.255.255   | /12  | شبكات متنوعة        |
| 192.168.0.0 – 192.168.255.255 | /16  | شبكات منزلية وصغيرة |

ملاحظة تقنية: تصنيفات Class A وClass B وClass C تاريخية، وتُستخدم هنا لتسهيل فهم الشرح. أما تصميم الشبكات الحديثة فيعتمد غالباً على CIDR وتقسيم الشبكات باستخدام Prefix Length.

***

#### 11. كيف تعمل NAT عملياً؟ (NAT in Practice)

لنربط الآن جميع المفاهيم السابقة بمثال واحد.

لنفترض أن لدينا شبكة منزلية تحتوي على الأجهزة التالية:

| الجهاز   | Private IP     |
| -------- | -------------- |
| Computer | 192.168.57.139 |
| Mobile   | 192.168.57.140 |
| Smart TV | 192.168.57.141 |
| Camera   | 192.168.57.142 |

جميع هذه الأجهزة متصلة بجهاز Router واحد.

عندما يحاول الكمبيوتر الوصول إلى موقع على الإنترنت، فإنه يرسل حركة البيانات إلى جهاز التوجيه.

يقوم جهاز التوجيه باستخدام NAT، وبالتحديد PAT في السيناريو المنزلي المعتاد، لترجمة معلومات الاتصال بحيث تخرج البيانات باستخدام عنوان IP العام للشبكة.

يمكن تصور العملية بالشكل التالي:

```
Computer ─────┐
Mobile ───────┤
Smart TV ─────┼── Router (NAT/PAT) ─── Internet
Camera ───────┘
                       |
                 Public IP
```

بهذه الطريقة تستطيع عدة أجهزة مشاركة عنوان IPv4 عام واحد.

وهذا أحد الأسباب الرئيسية التي ساعدت على استمرار استخدام IPv4 رغم محدودية عناوينه العامة.

***

#### 12. الخلاصة (Summary)

في هذا الدرس تعرفنا على الأساسيات التي تقوم عليها عملية العنونة في الشبكات.

أهم النقاط التي يجب أن تكون واضحة لديك:

1. عنوان IP هو عنوان منطقي يُستخدم لتحديد الأجهزة وتوجيه البيانات عبر الشبكات.
2. يعمل IPv4 وIPv6 ضمن الطبقة الثالثة (Layer 3) من نموذج OSI.
3. يتكون IPv4 من 32 Bit، موزعة على أربعة Octets.
4. كل Octet يتكون من 8 Bits، وتبلغ قيمته العشرية من 0 إلى 255.
5. يعتمد النظام الثنائي (Binary) على القيمتين 0 و1.
6. يوفر IPv4 حوالي 4.3 مليار عنوان ممكن.
7. يستخدم IPv6 حجم 128 Bit لتوفير مساحة هائلة من العناوين.
8. تسمح عناوين Private IP للأجهزة بالتواصل داخل الشبكات الخاصة.
9. تسمح تقنية NAT بترجمة عناوين الشبكة عند انتقال حركة البيانات بين الشبكات.
10. تُستخدم PAT لمشاركة عدة أجهزة عنوان IPv4 عاماً واحداً باستخدام المنافذ.
11. أجهزة Router مسؤولة عن توجيه حزم البيانات بين الشبكات.
